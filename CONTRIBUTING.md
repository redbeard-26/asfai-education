# Contributing

ASFAI Education welcomes contributions to its architecture, schemas, examples, mappings, and implementation plans.

## Before submitting a change

- Open or reference an issue for changes that affect identifiers, semantics, licensing, privacy, or interoperability.
- Keep objectives, evidence, assessment claims, and mastery states as distinct concepts.
- Cite the exact version of any external standard used by a proposal.
- Include provenance and licensing information for every proposed data source.
- Use neutral, evidence-backed language for claims about standards and conformance.
- Add examples or fixtures when introducing a new entity or relationship.

## Never submit

- student or family personally identifiable information;
- access tokens, credentials, or private URLs;
- raw student conversations or identifiable learning records;
- proprietary assessment items or curriculum materials;
- copied standards text without verified redistribution rights and required notices.

Synthetic learner data must be unmistakably fictional and should not be derived from a real student's record.

## Pull requests

Create a focused branch, make a small coherent change, and explain:

1. the problem being addressed;
2. the proposed behavior or model;
3. the standards and source versions involved;
4. privacy and licensing effects;
5. how the change was checked.

Schema changes should include a migration or compatibility note. Changes to mastery logic should include examples showing both successful and contradictory evidence.
